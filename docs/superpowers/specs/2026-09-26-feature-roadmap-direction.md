# 小维新功能与平台方向（Direction V0.3，方向已定、暂缓实施）

> **状态**：负责人于 2026-09-26 确认 F1–F5 的范围与顺序；本文件记录产品方向，不是详细实施计划，**不授权**源码、migration、Compose、真实连接、部署或 E1。每项开工前仍须有详细计划、exact-SHA 独立复审和明确开工口令；真实调用另需各自现场 GO。
> 当前进度与证据只看 [当前状态](../../../AGENT_HANDOFF.md#current-status)。

## 1. 已定方向

1. **不做旧小维能力整体迁移。** 旧实现与新架构不相容，不搬代码，也不以“功能对齐 51 项”为目标；旧能力清单只作需求备忘。
2. **按当前需求在新架构上重新设计。** 每个能力走 CapabilitySpec → 确定性 Planner → Policy / SQLGuard → ToolGateway adapter → Evidence → Render → Eval；审批走确定性治理组件。
3. **业务功能路线**：StarRocks 只读查询及 Web 结果页 → 导出审批 → CSV 导出；StarRocks 路线验证后再单独接入 TiDB；聊天记录与多轮记忆暂缓。
   旧能力清单仅作候选需求备忘：StarRocks 其他运维查询（当前查询、Profile、节点、导入、物化视图等）、巡检与报告、Dinky/Flink 只读诊断、Jenkins 只读状态、告警主动诊断、任务取消/重跑、DBA/值班职责与可靠通知。每项入选时单独立项，不从本文外推授权。
4. **部署形态方向**：收敛为两个容器（`postgres` + 一个 `xiaowei`），完整口径与已接受的权衡见 [当前状态](../../../AGENT_HANDOFF.md#current-status) 第 6 节。先本机，之后 RI6；两者均暂缓，分别需要详细计划与负责人 GO。`ARCHITECTURE.md` §11 和 `DEVELOPMENT_PLAN.md` M5/RI6 的现行分容器文本，在部署实施前再按计划修订，并决定是否补写或修订 ADR-001。W5-C（provider-off 产品壳部署）已于 2026-09-26 取消，W5 资产保留备用。
5. **对话能力横向方向（替代原 I3/I4 规划）**：未来重新设计自然沟通、缺槽澄清、进度/结果说明，以及通用、知识、运维和诊断请求分流。它不新增 F 编号，也不改变 F1–F5 顺序。I0–I2 已完成部分不受影响；I3/I4 原定义不再推进。
   - 该方向尚未形成详细范围或实现计划，不包含隐式多轮记忆，也不允许模型自行选择工具或执行。
   - 多轮对话记忆未获批准；如未来需要，须单独设计存储、权限、保留和审计并获 ADR 批准。
   - 跨 capability 组合与证据驱动的自主调查仍受现有架构限制，须另立 ADR 并获批准后才能实现。

## 2. 当前事实

- 当前已实现三个只读能力：`starrocks.slow_query.diagnose`、`prometheus.alert.evidence`、`asset.inventory.lookup`；能力证据与运行状态以 handoff 为准。
- **尚无通用数据库查询**：M6b 仅为慢查询诊断接入 StarRocks adapter，支持固定 operation，默认关闭；没有真实目标连接证据。
- **尚无查询结果 artifact、结果页、CSV 导出或结果访问/导出审批实现**；当前 W0–W5 不创建这些功能。新功能路线 F1–F3 会单独规划最小结果 artifact、受保护 Web 结果页及两类独立审批，不属于 W0–W5。
- **尚无 Admin 查看聊天/任务内容能力**；`AdminCapability.VIEW_PRIVATE_TASK_CONTENT` 尚无该类消费者。

## 3. 路线（按依赖顺序）

| 序 | 功能 | 已确认范围 | 前置与边界 |
| --- | --- | --- | --- |
| F1 | StarRocks 只读查询与锁定结果页 | 对单个已授权 StarRocks target，按其由 Admin 配置的 DBA 级只读凭据访问该 target 可达的全部数据库和表；任何已激活、已认证且能提交只读任务的用户均可查询，不另设逐人查询许可。查询执行本身不需要审批。F1 结果 artifact 保留 1 天；飞书卡片永不嵌入真实结果行，只发送受保护的 Web 结果链接；Web 详细结果默认锁定，需 F2 单独批准后查看。 | 确定性 SQL 模板与 AST 校验，不接受用户或模型直接提供的可执行 SQL。设置 `max_rows`、`max_bytes`、`query_timeout`；达到任一资源上限时明确标记不完整。结果访问遵守 requester/approver ACL，Admin 不因角色自动越权。真实 StarRocks 调用仍需独立现场 GO。 |
| F2 | Web 详细结果查看审批 | 首期只走飞书；每个结果的查看单独审批，由一名具备相应审批权限的人批准即可。该审批权限由 Admin 分配给具体用户，默认无人拥有；申请人可以自审，但仅当本人也获配该审批权限；审批有效期 1 小时。批准后申请人和该次查看审批人可在 Web 查看完整结果。 | 查看授权不等于 CSV 下载授权；不授予 E1。ADR-005 及拒绝、过期、冲突和审计契约须在详细计划中定稿。 |
| F3 | CSV 下载审批与导出 | CSV 是唯一导出格式；下载另走独立飞书审批，由一名具备相应审批权限的人批准即可。该审批权限由 Admin 分配给具体用户，默认无人拥有；申请人可以自审，但仅当本人也获配该审批权限；审批有效期 1 小时。查看审批不自动批准导出，导出审批也不自动批准 Web 详细查看。批准后申请人从 Web 结果页受控下载；CSV 文件保留 1 天。 | 下载授权/链接的具体生命周期、文件与查询结果的资源上限、CSV 安全处理在详细计划中明确；不能绕过 F1 的资源上限或把不完整结果标成完整。 |
| F4 | TiDB | TiDB 后续单独接入；先验证 StarRocks 路线，再独立设计、评审和排期。 | 不因共同使用 MySQL wire protocol 就假定 SQL 方言或语义相同；须有自己的 adapter、SQLGuard、测试/eval 和真实调用授权。 |
| F5 | Admin 历史查看 / 聊天记录 / 多轮记忆 | 聊天记录与多轮记忆暂缓；Admin 查看任务/聊天内容也暂缓，当前均不实现。 | 未来若重新启动，须先区分任务原文审计与对话上下文记忆，另定数据源、访问权限、保留期和审计。 |

F1 → F2 → F3 为首期顺序：先完成查询与锁定结果，再单独授权 Web 详细查看，最后单独授权 CSV 下载。Web 详细结果查看与 CSV 下载分别审批；每项审批都是独立请求，互不授权。F4 在 StarRocks 路线验证后单独启动；F5 暂缓。两类审批权限分别由 Admin 分配给具体用户，默认无人拥有；每项审批由一名具备相应权限的人批准，申请人仅在本人也获配该权限时可自审，审批有效期各为 1 小时。F1 详细计划必须逐项满足 Web 规格 §11.2 的六项前置条件，或写明不满足项的变更及理由；不得默认为这些前置已被方向批准豁免。各阶段均须先有详细计划、独立复审和开工授权。资源上限的数值、字段脱敏与具体存储实现属于详细计划，不在本方向文档中臆造。

## 4. 与既有文档和授权的关系

- `DEVELOPMENT_PLAN.md` V3.1 记录这一路线；它不改变 W0–W5、M8/E1、RI4、RI6、W4c 或部署授权。
- Web 产品规格中的“W0–W5 不创建结果 artifact / `/results`”仍适用于 W0–W5。本路线明确 R1 不再作为独立功能门，由 F1–F3 承接结果查询、访问和导出方向；这不等于完整通用 R1 结果平台已获批实现，也不豁免 Web 规格 §11.2 的六项前置条件；F1 详细计划须逐项满足这些条件，或说明不满足项的变更及理由。
- 当前 `ExecutionPlan` 绑定单一 capability，`Reflection` 不能追加步骤或选择工具；多证据源自适应诊断仍属 V1 非目标。F1 不授权跨 capability 组合或自主调查。
- E1（修改被管运维目标）持续关闭。导出审批与 E1 分离，不能相互推导授权。
- 与[完整功能部署验收总控计划](../plans/2026-09-25-full-feature-deployment-acceptance.md)并行：本文是新增业务功能方向，不代表已有能力的真实接入或发布证据。
